# 加分项完成后的模型覆盖率与推荐质量优化方案（历史基线）

> 状态：历史计划，已由 2026-09-02 实现与验证结果取代。
>
> 本文保留当时的决策与待办，不代表当前完成状态。TF-IDF、item-item CF、五源候选契约
> 和 validation 锁定混排已经实现；当前事实以 README、`docs/VERIFICATION.md` 和最新
> 模型 manifest 为准。

## 1. 当前背景

- 当前线上模型为隐式反馈 TruncatedSVD，发布版本
  `svd-20260902T022510026424Z-cccf5c24`，使用 32 维 item/user factors。
- 数据使用全局时间切分：最早 80% 为 train，随后 10% 为 validation，最后
  10% 为 test；相同时间戳不会跨分区。
- 当前 test 的 `item_coverage ≈ 0.237160` 表示：测试期目标正样本中，约
  23.716% 的 item 同时存在于 train-only 模型候选宇宙，能够被当前 SVD 打分。
  它不是目录覆盖率，也不是“模型命中了 23.716%”。
- `target positive` 是目标时间段内、符合评估用户口径的全部正样本；
  `scorable positive` 是其中 item 在训练候选宇宙内、当前模型可计算分数的子集。
  两者的差额必须保留并报告，不能从全量指标分母中悄悄删除。
- 当前线上在模型不可用、冷用户或候选不足时使用 train-only popular、数据库当前
  热度或 explore 作为 fallback；服务端在合并后统一执行下线过滤。

## 2. 风险解释

- Warm-item Recall/NDCG/HitRate 只衡量“模型能够打分”的子集，不能代表全部未来
  交互；单独展示这些指标会高估全量推荐能力。
- SVD 的 item vocabulary 来自训练期。测试期新出现或训练期未出现的内容没有
  latent factor，因此无法获得个性化 SVD 分数。
- 低 coverage 是模型质量与可服务范围风险，不是必选能力造假。当前实现明确报告
  target/scorable 数量和 coverage，并通过 popular/explore fallback 保证线上可用。
- 当前做法坚持 train-only 候选、时间切分和不可打分样本透明披露，符合防泄漏和
  诚实评估原则；不能为了提高数值使用未来 item 词表或最终累计 likes/views。

## 3. 第一阶段：评估体系完善

同时报告以下口径，所有指标注明 K、分母、候选池和负采样规则：

1. Warm-user/Warm-item Recall@K、NDCG@K、HitRate@K：仅分析可打分 cohort，
   但同时报告 cohort 规模。
2. Cold-item coverage：目标新 item 中能被非 SVD 召回源覆盖的比例。
3. 全量 Recall@K/NDCG@K：所有 target positives 进入分母，不可打分正样本按
   miss 计算。
4. Fallback-aware 最终混排指标：对 SVD、内容、热门和探索合并后的最终列表评估。
5. 按内容首次出现时间、训练期流行度、warm/cold 状态分桶，报告分桶样本量和指标。
6. 固定 K（建议 10/20）、100 个确定性负样本与全目录评估两套结果；记录 query
   checksum，确保模型之间使用同一批 query。

退出条件：报告能够同时回答 warm 质量、全量质量、cold 覆盖和最终混排质量，且
不可打分样本没有被隐藏。

## 4. 第二阶段：轻量内容召回

- 从训练期可见标题构造 TF-IDF；资源允许时再比较轻量文本向量，禁止使用测试期
  行为拟合表示。
- 使用用户在 cutoff 前的历史内容向量做加权聚合，生成用户内容偏好向量。
- 新内容仅依赖发布时可用标题进入内容召回，使其无需 SVD item factor 也可召回。
- 合并 SVD、内容、热门和探索候选；每个来源保留 source、raw score 和 model version。
- 在验证集上确定分数归一化方式和来源配额，合并后去重，并加入作者/标签多样性约束。
- 无标题、空标题或低质量标题降级到热门与探索，不伪造内容向量。

## 5. 第三阶段：混合推荐优化

- 增加 train-only item-item CF，覆盖有共现历史但文本质量较差的内容。
- 引入有明确可用时间的内容质量先验，禁止历史时点使用未来累计快照。
- 为新内容设置受控探索配额，并限制单作者/单标签集中度。
- 评估定时全量训练与增量更新；增量方案必须定义 cutoff、幂等和回放语义。
- 模型发布保留版本、校验和、原子 pointer、灰度观测与一键回滚；线上监控 fallback
  占比、来源分布、延迟、错误率和分桶效果。

## 6. 验收指标

建议在固定 test 与独立时间外推集上验收：

- 全量 Recall@10、NDCG@10 相对当前基线提升至少 15%，并报告置信区间。
- Warm Recall@10/NDCG@10 相对退化不超过 2%。
- Cold-item 可召回率达到 60% 以上，且不可通过改变 cold 定义制造提升。
- 个性化请求的 fallback 占比相对下降至少 20%。
- 推荐目录覆盖率和长尾覆盖率相对提升至少 20%。
- Intra-list diversity 或来源熵提升，且点击/喜欢离线代理指标不显著退化。
- CPU 单请求 P95 延迟保持在既定服务预算内；内容召回失败可降级到现有 popular/explore。
- 任何训练、特征、候选和评估步骤均满足 `event_timestamp <= feature_cutoff`，
  不得发生未来信息泄漏。

## 7. 实施优先级与依赖

| 顺序 | 阶段 | 前置依赖 | 预计工作量 | 主要风险 | 回滚方法 |
|---:|---|---|---:|---|---|
| 1 | 评估体系完善 | 冻结当前 test query 与指标定义 | 0.5–1 天 | 新旧口径混淆 | 保留当前 metrics 并并列输出 v2 |
| 2 | 标题 TF-IDF 内容召回 | 训练期标题快照、分词/规范化规则 | 1–2 天 | 标题噪声、冷用户无历史 | 关闭内容来源配额 |
| 3 | SVD+内容+热门+探索混排 | 来源归一化与离线混排评估 | 1–2 天 | 分数尺度偏置 | 回退当前 SVD+fallback |
| 4 | item-item CF 与质量先验 | cutoff-safe 共现和快照可用时间 | 1–2 天 | 稀疏性、快照泄漏 | 关闭对应召回源 |
| 5 | 定时/增量训练与线上观测 | 稳定发布、回滚、来源指标 | 2–4 天 | 版本漂移、运行复杂度 | 回滚原子 pointer |

推荐顺序严格为：先统一评估，再做轻量内容召回，再做混排，最后评估 CF 与增量训练。
每一阶段必须能独立关闭并回退，不依赖修改 coverage 定义。
